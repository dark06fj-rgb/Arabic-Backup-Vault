# Arabic Backup Vault

تطبيق Android لحفظ ملفات التعريب محلياً، مع إمكانية نقل الملفات إلى مستودعات GitHub العامة والخاصة.

## الوظائف

- استيراد ملفات منفردة إلى مساحة عمل خاصة بالتطبيق.
- إنشاء نسخ احتياطية يدوية وتلقائية قبل الاستبدال والاستعادة.
- إنشاء سجل SHA-256 وفحص سلامة النسخ.
- استعادة مرحلية وتصدير/استيراد ZIP مع فحوصات أمان للمسارات والحجم.
- استعراض ملفات مستودع GitHub وفرعه وتنزيل الملفات إلى مساحة العمل.
- رفع الملفات المختارة من مساحة العمل إلى GitHub، مع تحديث SHA الحالي عند استبدال ملف موجود.
- حفظ رمز GitHub محلياً مشفراً باستخدام Android Keystore (AES-GCM).

## ربط GitHub

1. افتح قسم «اتصال GitHub» داخل التطبيق.
2. اكتب اسم المستودع بصيغة `owner/repository` والفرع المطلوب.
3. يمكن تنزيل الملفات من المستودعات العامة دون رمز وصول.
4. للرفع، أنشئ Fine-grained personal access token مخصصاً لهذا المستودع فقط، مع صلاحية Repository contents: Read and write، ثم احفظه في التطبيق.
5. نزّل الملفات المطلوبة أو ارفع ملفاً من مساحة العمل. كل رفع ينشئ commit منفصلاً.

لا يرفع التطبيق الملفات تلقائياً، ولا يحذف الملفات البعيدة. تحقق من المستودع والفرع قبل كل عملية رفع. لا تشارك رمز الوصول مع أي شخص، ويمكن حذفه من التطبيق.

## الخصوصية وحدود الحفظ

- رمز GitHub لا يُكتب في ملفات المشروع أو السجلات؛ يُشفّر على الجهاز بمفتاح Android Keystore.
- الملفات تبقى محلياً إلى أن تختار رفعها يدوياً.
- حذف التطبيق أو مسح بياناته قد يحذف النسخ المحلية والرمز المحفوظ؛ صدّر ZIP إلى مكان آمن بشكل دوري.
- الاتصال بـ GitHub لا يعني اتصال ChatGPT بالتطبيق أو التحكم به عن بُعد؛ يجب أن تبدأ عمليات النقل من داخل التطبيق.

## البناء

يتطلب Android Studio وJDK 17 وAndroid SDK 35. افتح المشروع في Android Studio ثم نفّذ Gradle Sync وشغّل وحدة app.

## حدود النسخة الحالية

- لا توجد مزامنة تلقائية أو مزامنة جماعية ثنائية الاتجاه.
- كل ملف يُرفع في commit مستقل.
- اختبار الاتصال الفعلي والرفع والتنزيل يحتاج إلى رمز GitHub يضيفه المستخدم على هاتفه.

## جسر الأوامر البعيد (قيد التطوير)

أُضيفت بنية أولية على الفرع `remote-command-bridge` باستخدام Supabase:

- جدول أوامر يبدأ دائماً بالحالة `pending`، ولا ينفّذ التطبيق أي عملية قبل موافقة صريحة من داخل الهاتف.
- تسجيل جهاز برمز اقتران أحادي الاستخدام صالح لمدة 15 دقيقة، ثم مصادقة الجهاز بسر عشوائي يُخزّن محلياً بصورة مشفرة ولا يُحفظ نصه في قاعدة البيانات.
- واجهة Edge Function لاستلام الأوامر المعلقة، واعتمادها أو رفضها، وإرسال نتيجة التنفيذ.
- لا توجد سياسات وصول عامة لجداول الجسر؛ الوصول من التطبيق يمر عبر Edge Function، ولا يوضع مفتاح Supabase service-role في التطبيق.

### حالة جسر Supabase وChatGPT

على الفرع `remote-command-bridge` أضيفت المكونات التالية:

- تسجيل الجهاز بسر عشوائي محفوظ مشفراً باستخدام Android Keystore وAES-GCM.
- Edge Function باسم `vault-device` لاستقبال الأوامر وتحديث حالتها.
- Edge Function مستقلة باسم `vault-mcp` تتحدث ببروتوكول MCP عبر JSON-RPC وتستخدم رمز Bearer خاصاً محفوظاً في أسرار Supabase.
- أدوات MCP: `vault_list_devices` و`vault_request_file_list` و`vault_get_command`.
- طلب عرض الملفات يظل `pending` حتى يوافق المستخدم من الهاتف.
- عند الموافقة، يعرض التطبيق أسماء الملفات وأحجامها من مساحة العمل الخاصة بالتطبيق فقط (حد أقصى 200 ملف)، ثم يرسل النتيجة إلى Supabase.
- لا توجد أدوات كتابة أو حذف أو استعادة عبر MCP.

عنوان MCP بعد نشر الدالة:
`https://vkykokoaidykjmmytqxg.supabase.co/functions/v1/vault-mcp`

يلزم ضبط سر `VAULT_MCP_ACCESS_TOKEN` في Supabase Function Secrets بقيمة عشوائية قوية لا تقل عن 32 حرفاً، ثم نشر الدالة `vault-mcp`. لا تضع هذا الرمز أو مفتاح `service_role` داخل تطبيق Android أو مستودع GitHub.

### إعداد Supabase والاقتران

1. طبّق ملفات `supabase/migrations/` بالترتيب، وانشر الدالة `vault-device` مع `verify_jwt = false`.
2. من SQL Editor أنشئ رمزاً أحادي الاستخدام صالحاً 15 دقيقة:
   `select public.create_vault_enrollment_code();`
3. في شاشة «ربط Supabase» داخل التطبيق، أدخل رابط المشروع والمفتاح العام فقط (`anon` أو `publishable`) ورمز الاقتران واسم الجهاز.
4. لا تضع `service_role` في التطبيق ولا ترسله إلى أي شخص. رمز الاقتران لا يُستخدم إلا مرة واحدة وينتهي بعد 15 دقيقة.

يجب عدم إضافة تنفيذ لأوامر الكتابة أو الحذف أو الاستعادة قبل بناء موافقات ظاهرة على الهاتف، والتحقق من المسارات والأحجام، وإنشاء نسخة احتياطية قبل الاستبدال.


### إعداد خادم MCP

1. من Supabase Dashboard افتح Edge Functions ثم Secrets، وأضف `VAULT_MCP_ACCESS_TOKEN` بقيمة عشوائية قوية (32 حرفاً على الأقل).
2. انشر الدالتين `vault-device` و`vault-mcp` من مجلد `supabase/functions`، مع إعداد `verify_jwt = false` كما في `supabase/config.toml`. يتحقق `vault-mcp` من رمز Bearer الخاص به بنفسه.
3. في عميل MCP يدعم الخوادم البعيدة، استخدم عنوان MCP أعلاه والمصادقة Bearer بالرمز نفسه.
4. استدعِ `vault_list_devices` لمعرفة معرّف الجهاز، ثم `vault_request_file_list` لإرسال الطلب.
5. افتح تطبيق Android، أدخل المفتاح العام إذا طُلب، واضغط «فحص الأوامر»، ثم وافق على «موافقة وعرض الملفات». بعد ذلك استدعِ `vault_get_command` باستخدام معرّف الأمر لاستلام النتيجة.

ملاحظة: هذا يجهّز خادم MCP، لكنه لا يعني أن كل خطة ChatGPT تستطيع إضافة خادم MCP مخصص. يجب أن تدعم خطة ChatGPT والواجهة المستخدمة الاتصالات بخوادم MCP البعيدة. كما أن التطبيق لا يعمل كخدمة خلفية دائمة؛ يجب فتحه وفحص الأوامر يدوياً حالياً.
